# discord

Discord チャットプロバイダ `bmo-discord` です。基盤ライブラリ `bmo-chat` のチャットプロトコルを通じて、チャットの
receiver に対して Discord として振る舞います。読み取りモード、できること、部屋で使うダイアレクトを宣言し、ボット
アカウントで部屋を読み、宣言した動詞を送信し、部屋での発言を receiver に渡します。オーナー本人のアカウントは、
gateway が確認したあとで `human-reader` と `human-avatar` の声で送信します。Discord の規約がユーザーアカウントの
自動化を禁じているため、エージェント用に作ったアカウントは運用しません。

## テストとテストアカウント

- **ほとんどの振る舞いテストは先送りされています。** テストスイートには、スタンドインの gateway を相手にする宣言、
  部屋モード、ヒアリング、health、ドキュメント送信、メンバーのテストと、スタンドインの Discord を相手にする gateway の
  ボットトークン、オーナーアカウント、入力中・プレゼンス、メンバーのテストが含まれます。
- **宣言テスト**は、どのトークンが設定されていても、gateway がオーナーアカウントについて何と答えても、サービスが
  宣言するモードと機能が保たれることを確かめます。
- **ヒアリングテスト**は、gateway がそれぞれを聞いていると答えるとおりに `peopleTyping` と `presence` が宣言される
  こと、そしてサービスが入力中マークやプレゼンスの変化を、receiver 側が聞いている部屋についてだけ伝えることを確かめます。
- **health テスト**は、Discord アプリケーションがないときサービスが ready でありながら理由として欠けている設定を
  挙げ、すべてのモードが落ちていること、トークンが設定され gateway が ready と答えれば ready になること、gateway が
  応答しないか Discord がトークンを拒否したと答えれば ready でないことを確かめます。
- **ドキュメント送信テスト**は、ディスク上に保持されたファイルが gateway にインラインで送られること、ダイアレクトの
  ファイル上限を超えるものは gateway に問い合わせずサイズで拒否されることを確かめます。
- **メンバーテスト**は、部屋のメンバーが gateway の一覧どおりに返されること、gateway の `not-found` がメンバー未保持
  として扱われること、未設定のプロバイダは gateway に問い合わせずメンバーを保持しないことを確かめます。
- **ボットトークンテスト**(`gateway/tests/`)は、トークン未設定のとき gateway の health が ready でありつつトークンが
  ないと述べること、Discord がトークンを受け入れれば ready になること、Discord が拒否すればその拒否を示して ready で
  ないことを確かめます。
- **入力中・プレゼンステスト**(`gateway/tests/`)は、入力開始が番号付きの部屋で 10 秒のマークとして伝えられ、ボット
  アカウントやオーナーアカウント経由のプロバイダ自身の入力は伝えられないこと、他アカウントのための入力中送信が拒否
  されること、identify の intents、新しいセッションのギルドが Discord の状態をマッピングしたひとつの完全な一覧として
  伝えられること、各人がいる部屋とともに伝えられることを確かめます。
- **オーナーアカウントテスト**(`gateway/tests/`)は、gateway によるオーナーアカウントの確認と、`human-avatar` の送信
  には付き `human-reader` の送信には付かないプレフィックスを確かめます。
- **gateway のメンバーテスト**(`gateway/tests/`)は、DM のメンバーがその受信者とボットアカウントであること、ギルド
  チャンネルのメンバーがボットアカウントと Discord がまだ保持している書き手であること、それぞれがニックネーム、表示名
  またはユーザー名で呼ばれることを確かめます。
- **testbed の `personal-data` チェックは追跡中のすべてのファイルを読み**、メールアドレス、ホームパス、電話番号、
  トークン、プライベートネットワークアドレスを探し、見つかったものごとにファイル、行、種類を示します
  (`PERSONAL-DATA.md`)。
- **Discord のテストアカウントは接続されていない**ため、ここにあるものは実際の Discord サーバーでは一度も試されて
  いません。

## 構成

| フォルダ | 内容 |
|---|---|
| `src/` | サービス自身のパッケージ:宣言、`discord-markdown` ダイアレクト、プロトコルのルート、receiver との接続、生成された gateway クライアント(`seam.rs`) |
| `gateway/` | gateway。ボットアカウントのソケット、オーナーアカウントのトークン、REST 呼び出し、プロバイダの番号ストア、生成されたサービスクライアント(`seam.ts`)を持つ bun パッケージで、テストは `gateway/tests/` にあります |
| `policy/` | プロバイダの固定値:機能、`own-account` モードを非対応と宣言する際の規約の文言、オーナーアカウントのペース、番号の範囲、ダイアレクトの上限と書き方の一文 |
| `lang/` | このプロバイダが描く、人が読む文言:プラットフォームのラベルと、メッセージを渡すときに付けるマーク |
| `tools/` | `docs/openapi.json` から両方のクライアントを生成する `generate.ts` |
| `deploy/` | デプロイがリンクする二つのサービスユニット:Rust のサービスと bun の gateway |
| `tests/` | サービス唯一のテストハーネス `tests/main.rs` とそのモジュール:スタンドインの gateway(`stand_in.rs`)を相手にする宣言、部屋モード、ヒアリング、health、ドキュメント送信、メンバーのテスト |
| `docs/` | プロバイダが行うことの正式な記述 |

ルートには、サービス唯一のパッケージの Cargo マニフェスト、`VERSION` に記されたバージョン、`testbed.toml`
(このリポジトリをどうテスト・チェック・ビルド・デプロイするかの testbed 向け宣言)、testbed のチェックが読む韓国語
台帳、`settings.example.env`(両プロセスが読むすべての設定と中立的な例の値)、`PERSONAL-DATA.md`(ここに決して
置いてはならない個人データ)、`install.toml`(新しいマシンへのインストールに必要なものの宣言で、`bmo install` が読みます)、`rustfmt.toml`、`CLAUDE.md` があります。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/api.md` | プロバイダの固定 API:ワイヤーフォーマット、リソース、ルート、コード |
| `docs/openapi.json` | 同じ API を OpenAPI 3.1 で記述したもので、両方のクライアントはここから生成されます |
| `docs/boundary-api.md` | 境界:提供するルート、receiver 側への呼び出し、サービスと gateway の継ぎ目、設定、クライアント |
| `docs/discord.md` | プロバイダ:宣言、ソケット、どのアカウントが部屋に応答するか、動詞、ダイアレクト、番号付け、拒否 |
| `PERSONAL-DATA.md` | ここに決して置いてはならない個人データと、それを守るチェック |

## バージョン

- **リポジトリ全体でひとつのバージョンを使います。** `VERSION` がそれを保持し、パッケージのバージョンはそれと等しく、
  gateway の `package.json` も同じバージョンを持ちます。
- **バージョンはオーナーが宣言したリリースでのみ変わります。** bmo-chat の `docs/conventions.md` 「Versions」に
  記されているとおりです。コミット、デプロイ、修正、契約の変更では変わらず、デプロイはコミットで区別します。

## ビルドチェック

Cargo は testbed の Cargo 動詞を通じて実行され、共有のビルドディレクトリひとつでビルドします。インストール済みの
testbed に独自の Cargo 動詞がない場合は、`bmo cargo` が同じ動詞を担います。

```sh
bmo cargo check --all-targets
bmo cargo clippy --all-targets -- -D warnings
bmo cargo fmt --check
```

gateway の型は `gateway/` でチェックします。

```sh
bun install
./node_modules/.bin/tsc --noEmit
```

二つの継ぎ目クライアントは `docs/openapi.json` から生成されます。このドキュメントを変更したら再生成します。

```sh
bun tools/generate.ts
```
